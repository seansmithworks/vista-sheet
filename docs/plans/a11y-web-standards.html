vista-sheet accessibility plan

Project: vista-sheet 2026-10-07 Revised, awaiting your 3 calls
Answer

Seven fixes block the final publish. They close the last two WCAG Level A failures (keyboard-only move, autoplaying video) and make the sheet a true modal. Eight more fixes and six polish items ship after.

An independent critique found 29 problems in the first draft. All 29 are accepted, and one fix (the page-behind-the-sheet lock) is deliberately different from the critic's.

Decisions for you

1. How a mouse or touch user moves the trigger without dragging

Drag stays on by default either way: it is the product tagline, and it is how someone clears a disc that covers content.

Applied (A)

Keyboard arrow moves plus a public setAnchor. README ships a copy-paste "Move" menu recipe. Strict conformance depends on the site rendering that menu.

Alternative (B)

The package ships its own tap-to-move: long-press the trigger and the 7 anchor spots appear as tap targets. Conformant out of the box, but new UI for you to design.

Recommendation: A now, B goes to BACKLOG as a design brief.

2. Pause control for the sheet's video

Your accepted fork has the poster at rest and the video playing while the sheet is open.

Applied

No pause button. Close and Escape count as the "hide" in WCAG 2.2.2 for content the user chose to open. A pause/play recipe goes in the README.

Alternative

A built-in pause control part. New UI, so your call.

3. High-contrast border colour

With the OS "increase contrast" setting on, the sheet and trigger edge is about 1.1:1 against the page.

Applied

An opaque mid-grey border (#8e8e93 class), only under prefers-contrast: more.

Alternative

A different value. You dial the exact colour on the canvas.

Release gate

  • P0 must land before the final publish (0.2). 7 items. 0.1.1 stays as BACKLOG 35 defines it.
  • P1 (8) and P2 (6) ship after.
  • Blockers cleared by P0: keyboard-only move (WCAG 2.1.1, Level A) and autoplaying video (2.2.2, Level A).
  • One deliberate deviation from the critic: the page behind the sheet is released at the close request, not when the exit animation finishes. Otherwise page clicks would be swallowed for about 640ms, which is worse than today.

P0: blocks the final publish (7)

1. The sheet behaves like a real modal: the page behind it can't be clicked or tabbed into, and reopen-mid-close keeps working.

Technical detail
  • Inert while open. Walk up from each kept node (panel, two focus guards, backdrop, live regions like toasts) to body. Everything else gets inert.
  • Released at the close request. The trigger is tappable from the first close frame, as six existing specs require.
  • Focus guards are siblings outside the panel and route on relatedTarget. One Tab from the panel still reaches Close.
  • Guards and scroll lock run until exit-complete, so Tab mid-close stays in the panel.
  • Focus restore only if focus is on the body or inside the panel, so a page control clicked mid-close keeps focus.
  • Rewrites useDialogBehavior.ts; deletes per-press Tab ownership (lines 246-272).
  • Gate: existing geometry (l), (n), (n-shape), (p3), buttons:537, media:335, all of focus.spec.ts. New: page click blocked with dismissOnBackdrop={false}, iframe can't steal focus, native Tab order in radio groups, <details> and shadow roots, toast stays live.

2. Escape closes only the top-most layer and never interrupts typing.

Technical detail
  • New src/dismissLayers.ts: modal and preview Roots push to it; one document keydown listener in bubble phase.
  • Ignored when defaultPrevented, isComposing or keyCode === 229.
  • Gate: preview inside a sheet takes two Escapes; composition Escape doesn't close; a listbox that prevents Escape keeps the sheet open.

3. Keyboard users can move the trigger with arrow keys, and the move animates exactly like a drag.

Technical detail
  • Extract snapTo(anchor) from handleDragEnd (Trigger.tsx:543-551); reduced motion seats directly.
  • Pure adjacentAnchor(anchor, key) in anchors.ts. Arrows are physical, so RTL is identical.
  • Works when draggable && !open.
  • useVistaSheet().setAnchor becomes public (additive), routed through snapTo.
  • Hidden role="status" announces "Moved to bottom right." Translatable via new anchorAnnouncement prop.
  • Gate: Playwright over all 7 anchors: anchor value, onAnchorChange, live text, and wrapper/surface/Shadow centres agree during the move.

4. The trigger's video shows its poster until the sheet opens, then plays.

Technical detail
  • Implements your accepted fork (BACKLOG.md:14). In Media.tsx the trigger video drops autoPlay/loop, uses preload="none", stays on poster. The sheet side keeps autoplay.
  • Rewrite media.spec.ts:419-440; check canvas-autoplay.spec.ts for the same assumption.
  • Known seam: on close, the sheet's current frame morphs into the poster (frame 0). This is the existing "no playback handoff" strawman.

5. An accessibility scanner (axe, free) runs before every publish and fails on any violation.

Technical detail
  • @axe-core/playwright plus example/axe.spec.ts, inside test:geometry (already in prepublishOnly).
  • Pages: index, contact, buttons, list, media-card, video, link-preview, flagship. Not canvas, play, tune, surface.
  • States: closed, open-settled, preview-open, each in default and reduced motion.
  • Two passes (tags, then a separate label-content-name-mismatch builder) because the last runOnly wins.
  • Red-proof fixture: a trigger whose label omits its visible text must fail pass 2, or the gate is not trusted.

6. Public type mistakes get caught before publish, not by consumers.

Technical detail
  • New tsconfig.types.json (src plus src/types.test-d.tsx, no test files) and a typecheck script run first in prepublishOnly.
  • @ts-expect-error cases: Trigger aria-label still required; aria-describedby accepted on Sheet.
  • Bare tsc stays broken per L145 and is out of scope.

7. The README stops claiming things the code doesn't do, and documents what it now does.

Technical detail
  • Rewrite the "Known gap" at README.md:724-726; add browser floor, arrow keys, the "Move" menu recipe.
  • Add --vista-sheet-accent to the dark recipe; the scroll-padding-bottom plus bottom-padding recipe; the "label must contain visible text" rule; the Android back-gesture line.
  • Tick BACKLOG 13's reposition/video items when they land.

P1: after the final publish (8)

1. Screen readers hear a title and description automatically.

Technical detail

New <VistaSheet.Title> (h2) and <VistaSheet.Description> (p) register ids; Sheet sets aria-labelledby/aria-describedby. Dev error if a sheet opens with no name. Labelled gains a third arm, {} (additive).

2. Focus can return to whatever opened the sheet, not just the trigger.

Technical detail

Sheet finalFocus?: RefObject<HTMLElement|null>, additive. Default stays the trigger.

3. Sites can learn why the sheet is closing and veto it.

Technical detail

onOpenChange(open, { reason, event?, cancel() }). Reasons: trigger-press | close-press | escape-key | outside-press | swipe | imperative.

4. The page doesn't scroll or shift under the sheet on more sites.

Technical detail

Inline in the existing effect: lock html as well as body; skip padding when scrollbar-gutter: stable. iOS: verify on device first; add the position:fixed path only if that fails.

5. Close is named "Close" by default.

Technical detail

CloseProps['aria-label'] becomes optional, default "Close" (additive). Trigger keeps its required label.

6. Wrong asChild use fails loudly instead of silently.

Technical detail

Dev error on mode mismatch; the child renders unwrapped. Never a link inside a button.

7. Long sheets are always keyboard-scrollable.

Technical detail

<VistaSheet.Content> uses a ResizeObserver instead of window resize, and gets role="region" labelled by the Title.

8. The preview card closes when you Tab away, and warns if it contains links.

Technical detail

Findings m3 and m13 in the draft.

P2: polish, after the final publish (6)

  • Windows High Contrast keeps every edge visible. Forced-colors block: 1px solid CanvasText borders plus Highlight focus rings.
  • "Increase contrast" gets a stronger border. Decision 3.
  • Valid HTML inside the trigger button. Spans instead of divs on the trigger side.
  • Small correctness fixes. Unconditional useId() at Root.tsx:78; dev warning when reduceMotion={false} overrides the OS.
  • Rectangle labels with buttonWidth don't clip under text-spacing overrides. Strawman: ellipsis.
  • The iOS keyboard doesn't cover an input in a bottom sheet. visualViewport reposition. Also the video pause/play recipe (Decision 2).

Not planned: <style> hoisting goes to BACKLOG (risks the first-paint fix). Native <dialog> is a no for v1: it would lock the trigger for the whole close and break reopen-mid-close.

Browser floor (stated in README)

  • Supported: Safari and iOS Safari 16.2+, Chrome and Edge 111+, Firefox 113+.
  • Why: the shipped CSS already uses color-mix() (styles.module.css:168), so this floor exists today. inert fits under it.
  • Correction: the draft's "React 19 implies the floor" was wrong.
  • corner-shape stays progressive.

Manual check before the final publish

  • VoiceOver on Safari (macOS and iOS): can't swipe out of the dialog, Close is reachable, the move announcement is heard.
  • Tests are headless Chromium only; the cross-browser branch owns WebKit and Firefox.

Assumptions
  • A1. You accept the browser floor (already de facto via color-mix).
  • A2. Releasing the page at the close request beats holding it through the close.
  • A3. iOS 16.2+ honours overflow:hidden for touch scroll. Unverified on device.
  • A4. Repositioning counts as "functionality" under 2.1.1 and 2.5.7 (the conservative reading).
